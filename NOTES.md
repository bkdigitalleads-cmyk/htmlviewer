## The open-a-file proof

What is checked without a device:
- (a) Declared document types: app.json `ios.infoPlist` has CFBundleDocumentTypes for public.html (.html, .htm) and public.xhtml, and for public.plain-text, public.css, com.netscape.javascript-source, public.json, public.xml, public.svg-image and net.daringfireball.markdown, role Viewer, rank Alternate; UTImportedTypeDeclarations for public.xhtml, public.css and net.daringfireball.markdown; LSSupportsOpeningDocumentsInPlace false. `npx expo config --type introspect` and a scratch `npx expo prebuild` both show them in Info.plist. Expo SDK 57 needs no config plugin for this.
- (b) The hand-over path: the generated AppDelegate calls `super.application(app, open:url, options:)` (expo-linking's subscriber returns false) `|| RCTLinkingManager.application(...)`, so the file URL reaches React Native's Linking; App.tsx takes `file://` URLs from `getInitialURL` and the `url` event; src/library.ts copies the file into Documents/library/<dir>/ and deletes the Inbox copy. The pure parts (names, types, bytes, folder plan) are unit-checked.
- (c) Relative pictures and CSS: `node store/page-proof.mjs` writes the app's page copy of the bundled sample (Sample page.html with css/style.css and images/harvest.svg beside it) exactly as the app does and loads it by file:// URL in Chromium: the style sheet applies, the picture loads, a page script stays off, a web picture is blocked by the page's policy, and find reaches a match by fragment. Screenshots in docs/design/proof/.

What needs TestFlight: that the app shows in the share sheet and Open in from Mail, Files and Messages; that iOS hands over the Inbox copy and the app opens it (cold start and while running); WebKit's folder-only read access (loadFileURL with allowingReadAccessToURL) and that the page's policy allows the folder's file: loads in WebKit as it does in Chromium; that scripts are really off; fragment navigation for find in WKWebView; the PDF from expo-print with the inlined pictures; the system paste button; the editor's keyboard row and selection.

## TestFlight checklist (1.0.0 build 1), around a real case

1. Fresh install: the three intro screens (Mail attachment, page and code, PDF), the trial and reminder screens if the sandbox Apple ID can get a trial, the paywall: weekly first and preselected, prices from the store, X after 3 seconds. Close it: "Reading is free." then Home, empty, with Open a file, Paste code and Sample page.
2. Email yourself an .html file with a script and a web picture in it (any saved page or report works). On the iPhone, in Mail, tap the attachment, tap Share: HTML Viewer is in the row of apps (or under More). Tap it. The app opens on the file. Also try it with the app closed (swiped away) and with the app already open.
3. Read it: the page shows; the line "Scripts and web content are off for files from other apps." shows under the tabs. Tap Change: Scripts and Web content are off with their one-line reasons. Turn on Web content: the web picture loads. Turn it off again. Pinch to zoom; text size bigger and smaller; Dark page on and off.
4. Tap a web link in the page: it opens in the browser, not in the app. Come back: the app is where you left it.
5. View the source: tap Source. Colored code, line numbers. Wrap on and off from the top right. Copy all, then paste into Notes.
6. Find a word: in Page, tap Find in page, type a word that is on the page: "1 of N", every match marked, the arrows move to each one and the page scrolls to it. Done. In Source, Find marks the matches in the teal.
7. Export a PDF: tap PDF. "Saved as PDF." The PDF shows the page with its pictures and styles. Share it to yourself, Print (the print preview is fine), Save to Files; open it in Files.
8. Hit the PDF paywall: back, tap PDF again: the paywall opens ("A PDF of every page."). Close it with the X: back to the file, no PDF made.
9. Hit the Edit paywall: tap Edit (small lock): the paywall opens ("Fix it and see the change."). Buy the sandbox weekly. The editor opens.
10. Edit a line: change a heading, watch the live page follow; use the code keys row (Tab, <, >, quotes), undo and redo, find and replace one word and all. Save, Save as a new file: the new file opens. Back on Home both files are listed. Check that the email in Mail is unchanged.
11. Restore: on a second device or after deleting the app, Settings, Restore purchases; and from a paywall's Restore purchases.
12. The fourth file: on a free Apple ID (test menu, Act as a free user), open a fourth file: the paywall opens once ("Keep every file you open."), then the file opens; Home lists three and "1 older file is kept on this iPhone." Open a fifth in the same launch: no paywall.
13. Open a file from Files: Open a file, pick the sample's folder files (a page with its .css and picture) together: the page shows with its style. Open a .json, .md and .css file: they open in Source. Try an .mht: it says it does not open.
14. Paste code: Paste code, then the paste button: no "Allow Paste" prompt; the code opens as a new file with scripts on.
15. Messages and Files: send the .html file in Messages, tap it, Share, HTML Viewer; in Files, long-press the file, Share, HTML Viewer.
16. Dark mode at night, the largest Dynamic Type size, and VoiceOver on Home, the tabs and the toolbar.
17. The trial reminder notification a day before the sandbox trial ends; it is the only notification.

## Noticed, not changed

- Claiming public.plain-text (needed for .txt) also offers the app for any plain-text-like file (.py, .log, .sh). Those open as text in Source. Narrowing it would drop .txt.
- Files shared to the app one at a time from the share sheet each get their own folder, so a page shared without its pictures shows without them (or with web pictures once Web content is on). Keeping a page with its files works through Open a file, picking them together. Zip files and whole folders are not opened.
- A page that builds itself with scripts prints without that content: the PDF copy drops scripts. Turning Scripts on does not change the PDF.
- A page with no viewport tag gets one (device width) so plain pages read at a normal size; a fixed 600 or 800 point email layout then needs a sideways scroll or a pinch.
- Text size is CSS zoom on the page, so the layout reflows like the browser's page zoom rather than only the text growing.
- The editor is a plain text field: no coloring and no line numbers while typing. Smart quotes are expected to be off (autocorrect off); check on the device.
- Saving writes UTF-8. A file that declared another character set keeps its own meta tag in the saved file; in the app it shows fine (the page copy says UTF-8), but another app reading the saved file could read the old character set.
- The fourth-file paywall opens at most once per launch so reading an attachment is never interrupted twice; the brief says "on a fourth recent file being kept". Say if it should open every time, as Cash Counter's fourth save does.
- The paywall also opens from folders and source themes (both Pro), besides Edit, the second PDF, the fourth file and Settings.
- The rating ask is once ever per trigger (the engine's rule); the brief says at most one per launch, which once ever also meets.
- A file shared in on the very first launch waits behind onboarding and its paywall, then opens. Skipping onboarding for that first file would read better; it changes the paywall sequence, so it is Brian's call.
- The onboarding reminder screen asks for notification permission, but only when a free trial is on offer (the engine's sequence). The app itself needs no permission.
- The brief gives no prices. The renders use Cash Counter's ($4.99 a week with 3 days free, $19.99 a year, $24.99 once) as samples only.
- The design renders come from a react-native-web copy: the iOS keyboard and the code-key row, the system paste button, the share and print sheets and WebKit's PDF view are not in them; a word longer than the line in Source breaks on the phone but not in the web render (line 5 of 04-source).
- The code font's file names and licence carry its maker's name (assets/fonts); it is not shown anywhere a person reads.
- The shipped icon files are a plain teal stand-in until Brian picks one of the three options.
